---
title: "Choosing Your Implementation"
description: "Pick the write path setup that fits your backend: your existing API, Supabase, the reference write implementation, or a write API in your own stack."
---

Each option below gives you an `uploadData()` function and a write API. They differ in what you already have and what you need to deploy.

| Your setup | Start with |
| --- | --- |
| You already have an API that your app uses for writes. | [Use Your Existing API](/handling-writes/write-path/existing-api) |
| You use Supabase and don't need multi-operation transactions. | [Supabase: PostgREST Route](/handling-writes/write-path/supabase-postgrest) |
| You use Supabase and need transactions or custom write logic. | [Supabase: Edge Function Route](/handling-writes/write-path/supabase-edge-function) |
| You don't have a write API, and a Node.js backend works for you. | [Reference Write Implementation](/handling-writes/write-path/reference-write-implementation) |
| You don't have a write API, and want it in your own backend stack. | [Build Your Own Write API](/handling-writes/write-path/build-your-own-write-api) |

Whichever option you choose, [Write Path Concepts](/handling-writes/write-path/concepts) covers what every write API must do: authenticate writes, apply them before responding, and handle failures without blocking the upload queue.
