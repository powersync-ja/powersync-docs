If you don't have a write API and your backend doesn't run on Node.js, you can build one in your own stack. Follow the API contract of the [reference write implementation](/handling-writes/write-path/reference-write-implementation), so that you can use its reference connector as your app's `uploadData()`.

## Implement the Reference API Contract

An [OpenAPI spec](https://github.com/powersync-ja/powersync-reference-write-implementation/blob/main/backend/shared/powersync-reference-write-api.openapi.yaml) defines the API between the reference connector and the reference write API. To build the same write API in your stack:

1. Implement `POST /api/data` as defined in the OpenAPI spec.
2. Apply each transaction in its own database transaction, and return one result per transaction, in order.
3. Use the reference connector as it is, or port it to your app's SDK.

The error mappings in the reference repository's [`backend/shared/src/persistence`](https://github.com/powersync-ja/powersync-reference-write-implementation/tree/main/backend/shared/src/persistence) folder show which database errors are retryable and which cause rejected writes.

## Designing a Different API

You don't have to follow the reference contract. If you write your own `uploadData()`, your write API can use any style, such as REST, GraphQL, or gRPC. It can have one endpoint for all changes or one endpoint per table or operation. An endpoint that accepts a batch of changes needs fewer requests when your app makes many writes at once, such as during bulk imports.

Your API still has to meet the requirements in [Write Path Concepts](/handling-writes/write-path/concepts). [Use Your Existing API](/handling-writes/write-path/existing-api) describes what `uploadData()` must do for an API that you design.

For example backends in Django, Node.js, and other stacks, see [Example Projects](/intro/examples).
