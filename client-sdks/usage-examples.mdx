## Using Transactions to Group Changes

A transaction groups several writes into one unit. Either all of the writes are saved, or none of them are. PowerSync also queues the changes from one transaction for upload as a group.

These examples delete a list and its todos together, so the app never keeps todos for a deleted list.

<Tabs>
  <Tab title="JavaScript Web">
    `writeTransaction()` runs your callback inside a transaction. PowerSync saves the changes when the callback finishes, and rolls them back if the callback throws an error.

    ```js
    async function deleteList(db, listId) {
      await db.writeTransaction(async (tx) => {
        await tx.execute('DELETE FROM lists WHERE id = ?', [listId]);
        await tx.execute('DELETE FROM todos WHERE list_id = ?', [listId]);
      });
    }
    ```

    ```rust
        let mut writer = db.writer().await?;
        let tx = writer.transaction()?;
    
        tx.execute("DELETE FROM lists WHERE id = ?", params![id])?;
        tx.execute("DELETE FROM todos WHERE list_id = ?", params![id])?;
    
        tx.commit()?;
        Ok(())
    }
    ```

## Insert, Update, and Delete Data in the Local Database

Write to the local SQLite database with standard SQL `INSERT`, `UPDATE`, and `DELETE` statements. PowerSync applies each write locally right away and queues it for upload to your backend.

The insert examples use `uuid()`, a SQL function that PowerSync provides, to generate an ID for each new row.

## Send Changes in Local Data to Your Backend Service

PowerSync does not write to your source database directly. While the app is connected, the Client SDK calls the `uploadData()` method of your backend connector whenever local changes are waiting in the upload queue. Your implementation sends these changes to your backend API, which applies them to your source database.

The examples below take the oldest queued transaction, send all of its changes to your backend, and then mark the transaction as complete. Each change includes the operation (`PUT`, `PATCH`, or `DELETE`), the table, the row ID, and the changed data. `backendApi` stands for your own API client. If the upload fails, throw an error. The SDK then keeps the changes in the queue and retries later.

To generate a complete backend connector for your SDK, open your instance in the [PowerSync Dashboard](https://dashboard.powersync.com/), select **Client SDK Setup**, and select your app language.

<Tabs>
  <Tab title="JavaScript Web">
    `getNextCrudTransaction()` returns the oldest transaction in the upload queue, or `null` if the queue is empty. Call `complete()` only after your backend has accepted the changes.

    ```js
    async function uploadData(database) {
      const transaction = await database.getNextCrudTransaction();
      if (!transaction) return;
    
      await backendApi.uploadChanges(transaction.crud);
      await transaction.complete();
    }
    ```

## Accessing PowerSync Connection Status Information

The sync status tells you whether the app is connected to the PowerSync Service, and whether data is uploading or downloading. Use it to show a connection indicator in your UI.

<Tabs>
  <Tab title="JavaScript Web">
    `connected` holds the current connection state. `registerListener()` calls `statusChanged` whenever the status changes, and returns a function that removes the listener. This React component uses both to show the connection state.

    ```jsx
    import * as React from 'react';
    
    export function ConnectionStatus({ db }) {
      const [connected, setConnected] = React.useState(db.connected);
    
      React.useEffect(() => {
    ```

## Wait for the Initial Sync to Complete

When a user first opens your app, the local database has no synced data until the first sync finishes. PowerSync gives you two ways to know when that first full sync has completed:

- `hasSynced` is a property of the sync status. It becomes `true` once the first full sync has completed. Use it in UI code that updates when the status changes, for example to show a loading screen instead of an empty list.
- `waitForFirstSync()` waits until the first full sync has completed, then returns. Use it in code that needs the synced data before it continues, for example before a query that runs at startup.

If the first sync completed in an earlier app session, `hasSynced` is already `true` and `waitForFirstSync()` returns right away.

## Wait for Local Data to Catch Up

The first sync may have completed in an earlier app session, so `hasSynced` and `waitForFirstSync()` don't tell you whether local data is up to date now. To wait until the local database has caught up with the server as of now, use [Sync Catch-Up](/client-sdks/checkpoint-requests): request a checkpoint, then wait for it to sync. Most of these examples use it for a refresh action, so the refresh indicator stops only once the device has caught up.

Checkpoint requests are in alpha. They require PowerSync Service v1.24.0 or later, and you must enable them with the `checkpointMode` option when calling `connect()`. See [Prerequisites](/client-sdks/checkpoint-requests#prerequisites).

<Tabs>
  <Tab title="JavaScript Web">
    `requestCheckpoint()` asks the PowerSync Service for a checkpoint. `waitForSync()` resolves once the local database has synced that checkpoint. This React button stays disabled while it waits.

    ```tsx
    import { useState } from 'react';
    import { usePowerSync } from '@powersync/react';
    
    export function RefreshButton() {
      const powerSync = usePowerSync();
      const [refreshing, setRefreshing] = useState(false);
    
      async function refresh() {
        setRefreshing(true);
        try {
          const checkpoint = await powerSync.requestCheckpoint();
          await checkpoint.waitForSync();
        } catch (e) {
          // Show the error to the user
        } finally {
          setRefreshing(false);
        }
      }
    
      return (
        <button onClick={refresh} disabled={refreshing}>
          {refreshing ? 'Refreshing...' : 'Refresh'}
        </button>
      );
    }
    ```

## Report Sync Download Progress

While a download is in progress, the sync status reports how many operations have downloaded out of the total. Use it to show a progress bar, especially during a long first sync. When no download is active, there is no progress value.

Several of these examples accept an optional priority. With a priority, they show progress toward the data with that priority instead of the full sync. See [Prioritized Sync](/sync/streams/prioritized-sync).

<Tabs>
  <Tab title="JavaScript Web">
    `useStatus()` returns the current sync status and re-renders the component when it changes. `downloadProgress.downloadedFraction` is a value from 0.0 to 1.0. This example uses [MUI](https://mui.com) components.

    ```tsx
    import { Box, LinearProgress, Stack, Typography } from '@mui/material';
    import { useStatus } from '@powersync/react';
    import type { FC } from 'react';
    
    export const SyncProgressBar: FC<{ priority?: number }> = ({ priority }) => {
      const status = useStatus();
      const progressUntilNextSync = status.downloadProgress;
      const progress = priority == null ? progressUntilNextSync : progressUntilNextSync?.untilPriority(priority);
    
      if (progress == null) {
        return <></>;
      }
    
      return (
        <Stack direction="column" spacing={1} sx={{ p: 4 }} alignItems="stretch">
          <LinearProgress variant="determinate" value={progress.downloadedFraction * 100} />
          <Box sx={{ alignSelf: 'center' }}>
            {progress.downloadedOperations == progress.totalOperations ? (
              <Typography>Applying server-side changes</Typography>
            ) : (
              <Typography>
                Downloaded {progress.downloadedOperations} out of {progress.totalOperations}.
              </Typography>
            )}
          </Box>
        </Stack>
      );
    };
    ```

    ```cs
    using PowerSync.Common.Client;
    using PowerSync.Common.DB.Crud;
    
    class SyncProgressBar
    {
        private PowerSyncDatabase _db;
        private int? _priority; // Optional: when set, show progress towards this priority instead of the full sync
        private SyncStatus? _currentStatus;
    
        public SyncProgressBar(PowerSyncDatabase db, int? priority = null)
        {
            _db = db;
            _priority = priority;
        }
    
        public async Task StartListeningAsync(CancellationToken ct = default)
        {
            var listener = _db.Events.OnStatusChanged.ListenAsync(ct);
            await foreach (var update in listener)
            {
                _currentStatus = update.Status;
                DisplayProgress();
            }
        }
    
        public void DisplayProgress()
        {
            var status = _currentStatus;
            var totalProgress = status?.DownloadProgress();
    
            var progress = _priority == null 
                ? totalProgress 
                : totalProgress?.UntilPriority(_priority.Value);
    
            if (progress != null)
            {

                var downloadedOps = progress.DownloadedOperations;
                var totalOps = progress.TotalOperations;
    
                Console.WriteLine($"Sync progress: {fraction * 100:F1}%");
    
                if (downloadedOps == totalOps)
                {
                    Console.WriteLine("Applying server-side changes...");
                }
                else
                {
                    Console.WriteLine($"Downloaded {downloadedOps} out of {totalOps} operations");
                }
            }
        }
    }
    ```

    ```rust
    use futures_lite::StreamExt;
    use powersync::PowerSyncDatabase;
    
    async fn print_progress(db: &PowerSyncDatabase) {
        let stream = db.sync_stream("lists", None);
        let mut status = db.watch_status();
        while let Some(status) = status.next().await {
            let progress = status
                .for_stream(&stream)
                .and_then(|stream| stream.progress);
    
            if let Some(progress) = progress {
                println!(
                    "Stream progress: {} out of {}",
                    progress.downloaded, progress.total
                );
            }
        }
    }
    ```
