## Metrics Endpoint

PowerSync exposes instance metrics via a Prometheus-compatible endpoint. This allows you to integrate with Prometheus or other monitoring systems that scrape Prometheus endpoints.

<Note>
  It's not recommended to scrape the Prometheus endpoint manually, we suggest using Prometheus or other compatible tools. PowerSync does not currently support pushing to OpenTelemetry collectors.
</Note>

#### Configuration

1. To enable metrics, update your PowerSync YAML file to include the `prometheus_port` and set a port number.

```yaml service.yaml
telemetry:
  # Set the port at which the Prometheus metrics will be exposed
  prometheus_port: 9090
```

2. Update your Docker compose file to forward the `prometheus_port`.

```yaml docker-compose.yaml
ports:
  # Forward port 8080 for the PowerSync Service
  - 8080:8080
  # Forward port 9090 for Prometheus metrics
  - 9090:9090
```

Once enabled, restart the service and the metrics endpoint will return Prometheus-formatted metrics, as described in the [What is Collected](/maintenance-ops/self-hosting/usage-reporting#what-is-collected) section of the [Usage Reporting](/maintenance-ops/self-hosting/usage-reporting) docs.

<Note>
  If you're running multiple containers (e.g. splitting up replication containers and API containers) you need to scrape the metrics separately for each container.
</Note>

## Metrics

### `powersync_sync_connections_total`

Allows you to monitor sync connection errors and rejected attempts, identify recurring error codes or rejection reasons.

#### Fields

Each series has an `outcome`, `close_reason`, `error_code` and `transport` (`http_stream` or `rsocket`) labels.

<Accordion title="Outcomes, Close Reasons, and Error Codes">
  ##### Outcome `ok`

  Closed without a stream error.

  - Close reasons: `client_closed`, `service_closed`, `process_shutdown`, or `unknown`
  - Includes token expiry, Sync Config switches, and client-side failures. Does not confirm successful sync.
  - Error code is ommited.

  ##### Outcome `error`

  Closed with a stream error.

  - Close reason: `stream_error`
  - Error code: PowerSync error code or `other`

  ##### Outcome `rejected`

  Connection attempt rejected.

  | close_reason | error_code |
  | --- | --- |
  | `service_unavailable` | `PSYNC_S2003` |
  | `no_sync_config` | `PSYNC_S2302` |
  | `storage_error` | PowerSync error code or `other` |
  | `sync_config_error` | PowerSync error code or `other` |
  | `concurrency_limit` | RSocket: `PSYNC_S2304`, HTTP: `other` |

  `storage_error` and `sync_config_error` are failures to load or parse the active Sync Config.

  See [Error Codes](/debugging/error-codes) for the meaning of each `PSYNC_` code.
</Accordion>

#### Use Case Examples

Below are some queries to help you troubleshoot sync connection issues.

##### Did Connection Failures Increase After a Deployment?

Graph this query across the deployment window to check for increased errors or rejections:

```promql
sum by (outcome, transport) (rate(powersync_sync_connections_total[5m]))
```

##### Which Errors Are Interrupting Sync?

If sync is interrupted, check which stream errors occurred in the last hour:

```promql
sum by (error_code, transport) (
  increase(powersync_sync_connections_total{outcome="error"}[1h])
) > 0
```

##### Why Can't Clients Establish a Sync Connection?

If clients cannot start syncing, check for rejected attempts in the last hour:

```promql
sum by (close_reason, transport) (
  increase(powersync_sync_connections_total{outcome="rejected"}[1h])
) > 0
```

Use the rejection reason to check the active Sync Config, connection limit, or Service logs.

<Note>
  `powersync_concurrent_connections` remains the gauge for streams that are currently open.

  Requests that fail authentication or validation are not counted.

  Series are not initialized to zero, so `rate()` and `increase()` can miss the first error or rejection.
</Note>
