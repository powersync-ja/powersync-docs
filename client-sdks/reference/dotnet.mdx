## Supported Frameworks and Targets

The PowerSync .NET SDK supports:

- **.NET Versions**: 8 (desktop-only), 9, and 10
- **MAUI**: Cross-platform support for Android, iOS, Mac Catalyst, and Windows (targeting `net9.0` and `net10.0` mobile frameworks)
- **WPF**: Windows desktop applications
- **Console/CLI**: Windows (x64, ARM), macOS (x64, ARM), and Linux (x64, ARM)

**Current limitations:**

- Blazor (web) platforms are not yet supported.

For more details, see the package [README](https://github.com/powersync-ja/powersync-dotnet/tree/main?tab=readme-ov-file).

### 1. Define the Client-Side Schema

<SdkClientSideSchema />

<GenerateSchemaAutomatically />

You can use [this example](https://github.com/powersync-ja/powersync-dotnet/blob/main/demos/CommandLine/AppSchema.cs) as a reference when defining your schema.

The available column types are `text`, `integer`, and `real`. These should match the values produced by your Sync Streams. If a value does not match, it is cast automatically. For details on how source database types map to SQLite types, see [Types](/sync/types).

#### Schema Definition Syntax

There are two supported syntaxes for defining the schema:

**Attribute-based (recommended):** Annotate a C# class with [`[Table]`](https://powersync-ja.github.io/powersync-dotnet/api/PowerSync.Common.DB.Schema.Attributes.TableAttribute.html), [`[Column]`](https://powersync-ja.github.io/powersync-dotnet/api/PowerSync.Common.DB.Schema.Attributes.ColumnAttribute.html), and [`[Index]`](https://powersync-ja.github.io/powersync-dotnet/api/PowerSync.Common.DB.Schema.Attributes.IndexAttribute.html) attributes:

```cs
using PowerSync.Common.DB;
using PowerSync.Common.DB.Schema;
using PowerSync.Common.DB.Schema.Attributes;

[Table("todos"), Index("list", ["list_id"])]
public class Todo
{
    [Column("id")]
    public string TodoId { get; set; }

    [Column("list_id")]
    public string ListId { get; set; }

    [Column("created_at")]
    public string CreatedAt { get; set; }

    [Column("completed")]
    public bool Completed { get; set; }
    // ... other columns
}

public static Schema PowerSyncSchema = new Schema(typeof(Todo));
```

<Note>
  Unlike the other syntaxes where PowerSync automatically creates an `id` column, the attribute-based syntax requires you to explicitly declare it. The SDK identifies the `id` property by looking for either a property named `id`, or any property with a `[Column("id")]` attribute (case-insensitive). Having none or more than one is an error.
</Note>

<Accordion title="Alternative: object initializer syntax">
  If you prefer to keep your schema definition separate from your data classes, you can use the object initializer syntax instead:

  ```cs
  using PowerSync.Common.DB.Schema;
  
  class AppSchema
  {
      public static Table Todos = new Table
      {
          Name = "todos",
          Columns =
          {
              ["list_id"] = ColumnType.Text,
              ["created_at"] = ColumnType.Text,
              ["completed"] = ColumnType.Integer,
              // ... other columns
          },
          Indexes =
          {
              ["list"] = ["list_id"]
          }
      };
  
      public static Schema PowerSyncSchema = new Schema(Todos);
  }
  ```
</Accordion>

### 2. Instantiate the PowerSync Database

Next, instantiate the PowerSync database. PowerSync streams changes from your backend source database into the client-side SQLite database, based on your Sync Streams. Your app reads from and writes to this local database whether the user is online or offline.

**Example:**

```cs
using PowerSync.Common.Client;
// If using MAUI:
// using Microsoft.Maui.Storage;

class Demo
{
    static async Task Main()
    {
        string dbLocation = "tododemo.db";

        // If using MAUI, ensure the DB file is stored in a platform-appropriate location
        // dbLocation = Path.Combine(FileSystem.AppDataDirectory, dbLocation);

        var db = new PowerSyncDatabase(new PowerSyncDatabaseOptions
        {
            Database = new SQLOpenOptions { DbFilename = dbLocation },
            Schema = AppSchema.PowerSyncSchema,
        });
        await db.Init();
    }
}
```

### 3. Integrate with Your Backend

The backend connector gives the SDK the credentials it needs to connect to your PowerSync instance and download data. It also uploads your app's local writes to your backend. The connector must implement two methods:

1. [IPowerSyncBackendConnector.FetchCredentials](https://powersync-ja.github.io/powersync-dotnet/api/PowerSync.Common.Client.Connection.IPowerSyncBackendConnector.FetchCredentials.html) - The SDK calls this method to get authentication credentials. It caches the credentials and calls the method again only when needed, for example on the first connection or when the token is near expiry. See [When `fetchCredentials()` is Called](/configuration/app-backend/client-side-integration#when-fetchcredentials-is-called) for details and [Authentication Setup](/configuration/auth/overview) for how to generate credentials.
2. [IPowerSyncBackendConnector.UploadData](https://powersync-ja.github.io/powersync-dotnet/api/PowerSync.Common.Client.Connection.IPowerSyncBackendConnector.UploadData.html) - The SDK queues local writes and calls this method to send them to your write endpoint, which applies them to the source database. If your app only reads synced data for now, you can implement this method later. To pick how to upload writes, see [Choosing Your Setup](/handling-writes/write-path/choosing-your-setup).

**Example:**

```cs
using System;
using System.Threading.Tasks;
using PowerSync.Common.Client;
using PowerSync.Common.Client.Connection;

public class MyConnector : IPowerSyncBackendConnector
{
    // User credentials for the current session
    public string UserId { get; private set; }
    
    // PowerSync instance URL
    private readonly string _powerSyncUrl;

    public MyConnector()
    {
        // In a real app, this would come from your authentication system
        UserId = "user-123"; 
        
        // Configure your PowerSync instance URL
        _powerSyncUrl = "https://your-powersync-instance.powersync.journeyapps.com";
    }

    public async Task<PowerSyncCredentials?> FetchCredentials()
    {
        try {
            // Implement fetchCredentials to obtain a JWT from your authentication service. 
            // See https://docs.powersync.com/configuration/auth/overview

            var authToken = "your-auth-token"; // Use a development token (see Authentication Setup https://docs.powersync.com/configuration/auth/development-tokens) to get up and running quickly

            // Return credentials with PowerSync endpoint and JWT token
            return new PowerSyncCredentials(_powerSyncUrl, authToken);
            
        }
        catch (Exception ex)
        {
            Console.WriteLine($"Error fetching credentials: {ex.Message}");
            throw;
        }
    }

    public async Task UploadData(IPowerSyncDatabase database)
    {
        // Implement UploadData to send local changes to your backend service
        // Leave it empty if you only want to sync data from the server to the client
        // To pick how to upload writes, see https://docs.powersync.com/handling-writes/write-path/choosing-your-setup
    }
}
```

With your database instantiated and your connector ready, call [`Connect`](https://powersync-ja.github.io/powersync-dotnet/api/PowerSync.Common.Client.PowerSyncDatabase.Connect.html) to start syncing data with your backend:

```cs
await db.Connect(new MyConnector());
await db.WaitForFirstSync(); // Optional, to wait for a complete snapshot of data to be available
```

## Using PowerSync: CRUD Functions

Once the PowerSync database is connected and your streams have synced, the data is in the local SQLite database.

The most commonly used CRUD functions to interact with your SQLite data are:

- [`PowerSyncDatabase.Get`](https://powersync-ja.github.io/powersync-dotnet/api/PowerSync.Common.Client.PowerSyncDatabase.Get.html) - get (`SELECT`) a single row from a table.
- [`PowerSyncDatabase.GetAll`](https://powersync-ja.github.io/powersync-dotnet/api/PowerSync.Common.Client.PowerSyncDatabase.GetAll.html) - get (`SELECT`) a set of rows from a table.
- [`PowerSyncDatabase.Watch`](https://powersync-ja.github.io/powersync-dotnet/api/PowerSync.Common.Client.PowerSyncDatabase.Watch.html) - execute a read query every time a dependent table changes.
- [`PowerSyncDatabase.Execute`](https://powersync-ja.github.io/powersync-dotnet/api/PowerSync.Common.Client.PowerSyncDatabase.Execute.html) - execute a write (`INSERT`/`UPDATE`/`DELETE`) query.

### Mapping Rows to Objects

By default, the read methods return rows. Each row holds the values of the columns that your query selects. You read each value by passing its column name to the corresponding method for its type, such as `GetString("description")`.

`Get` and `GetOptional` return a single row. `GetAll` and `Watch` return a `QueryResult`, with the rows in its `Rows` property:

```cs
QueryResult result = await db.GetAll("SELECT description, completed_at FROM todos");

foreach (IQueryRow todo in result.Rows)
{
    string description = todo.GetString("description");
    // completed_at is NULL until the todo is completed, so read it with an OrNull method
    DateTime? completedAt = todo.GetDateTimeOrNull("completed_at");
}
```

Rows work well for dynamic queries, where you don't know the shape of the data ahead of time. When you do know it, you usually want a list of regular C# objects that you can pass to the rest of your app, such as your UI.

Instead of building that list yourself in a loop, tell the read method how to convert each row, and it returns the list. You can do this in two ways:

- **Mapper function:** Pass the read method a function that converts a row. Use it for one-off queries, or to get a single value from each row.
- **Result type:** Implement `IFromRow<T>` on your class, so the class converts rows itself, and pass the class as the type argument. Use it to map a table or query to a class that you use throughout your app, since every query reuses the same conversion.

<Tabs>
  <Tab title="Mapper Function">
    ```cs
    // Convert each row to a tuple, without defining a class
    var todos = await db.GetAll(
        "SELECT description, completed_at FROM todos",
        null,
        row => (
            Description: row.GetString("description"),
            CompletedAt: row.GetDateTimeOrNull("completed_at"))
    );
    // Or, extract a value from a row in a single step
    bool latestTodoIsCompleted = await db.Get(
        "SELECT completed FROM todos ORDER BY created_at DESC",
        null,
        row => row.GetBool("completed"));
    ```
  </Tab>
  <Tab title="Result Type">
    ```cs
    using PowerSync.Common.DB;
    
    public class TodoItem : IFromRow<TodoItem>
    {
        public string Description { get; set; } = "";
        public DateTime? CompletedAt { get; set; }
    
        public static TodoItem FromRow(IQueryRow row) => new()
        {
            Description = row.GetString("description"),
            CompletedAt = row.GetDateTimeOrNull("completed_at")
        };
    }
    
    List<TodoItem> todos = await db.GetAll<TodoItem>("SELECT description, completed_at FROM todos");
    ```
  </Tab>
</Tabs>

#### Generating Row Mappers

If you have many result types, the [`PowerSync.Common.SourceGenerators`](https://github.com/powersync-ja/powersync-dotnet/tree/main/PowerSync/PowerSync.Common.SourceGenerators) package can generate the conversion for each one at compile time, so you don't need to write it yourself. This package is currently in [alpha](/resources/feature-status).

```bash
dotnet add package PowerSync.Common.SourceGenerators --prerelease
```

Mark a `partial` class, struct, or record with `[GenerateSqlMapper]`. This example is the `TodoItem` result type from above, without the conversion:

```cs
using PowerSync.Common.DB;
using PowerSync.Common.DB.Schema.Attributes;

[GenerateSqlMapper]
public partial class TodoItem
{
    [Column("description")]
    public string Description { get; set; } = "";

    [Column("completed_at")]
    public DateTime? CompletedAt { get; set; }
}

List<TodoItem> todos = await db.GetAll<TodoItem>("SELECT description, completed_at FROM todos");
```

Each property reads the column named by its `[Column]` attribute, the same attribute that your schema classes use. Without the attribute, the property reads the column with the same name, ignoring case. The generator does not convert between naming styles, so `CompletedAt` needs `[Column("completed_at")]` to read the `completed_at` column. For the full mapping rules and supported types, see the [package README](https://github.com/powersync-ja/powersync-dotnet/blob/main/PowerSync/PowerSync.Common.SourceGenerators/README.md).

### Fetching a Single Item

The `Get` method executes a read-only (SELECT) query and returns a single result. It throws an exception if no result is found. Use `GetOptional` to return a single optional result (returns `null` if no result is found).

```cs
// Find a todo by ID
var todo = await db.Get<TodoItem>("SELECT * FROM todos WHERE id = ?", [todoId]);
```

### Querying Items (PowerSync.GetAll)

The `GetAll` method returns a set of rows from a table.

```cs
// Get all list IDs
var listIds = await db.GetAll("SELECT id FROM lists", null, row => row.GetString("id"));
```

### Watching Queries (PowerSync.Watch)

The `Watch` method executes a read query whenever a change to a dependent table is made. It returns an `IAsyncEnumerable` so you can use `await foreach` to consume results.

<DotNetWatch />

### Mutations (PowerSync.Execute)

The `Execute` method can be used for executing single SQLite write statements.

```cs
// And db.Execute for inserts, updates and deletes:
await db.Execute(
  "INSERT INTO lists (id, name, owner_id, created_at) VALUES (uuid(), 'New list', ?, datetime())",
  [connector.UserId]
);
```

## Waiting for the Latest Server Data

<CheckpointRequestsIntro />

```cs
// Opt in when connecting
await db.Connect(
    new MyConnector(),
    new PowerSyncConnectionOptions(checkpointMode: new CheckpointMode.Requests())
);

// Later: wait until local data is up to date
var checkpoint = await db.RequestCheckpoint();
await checkpoint.WaitForSync().WaitAsync(TimeSpan.FromSeconds(30));
```

## Configure Logging

By default, the SDK uses a no-op logger that outputs nothing. To enable logging, configure a logger with .NET's `ILogger` interface:

```cs
using Microsoft.Extensions.Logging;
using PowerSync.Common.Client;

// Create a logger factory
ILoggerFactory loggerFactory = LoggerFactory.Create(builder =>
{
    builder.AddConsole();             // Enable console logging
    builder.SetMinimumLevel(LogLevel.Information);  // Set minimum log level
});

var logger = loggerFactory.CreateLogger("PowerSyncLogger");

var db = new PowerSyncDatabase(new PowerSyncDatabaseOptions
{
    Database = new SQLOpenOptions { DbFilename = "powersync.db" },
    Schema = AppSchema.PowerSyncSchema,
    Logger = logger
});
```

## Upgrading the SDK

To upgrade the PowerSync package, run the following command in your project folder:

```bash
dotnet add package PowerSync.Common
```

### Upgrading to .NET SDK v1

Version 1 of the .NET SDK (v1.0.1 and later) has breaking API changes from the beta SDK (v0.x). This section describes the changes that you must make to upgrade.

#### Target .NET 8 or Later

The SDK no longer supports .NET Standard 2.0, .NET Framework 4.8 or .NET 6. Desktop and console apps must target .NET 8 or later. MAUI apps must target .NET 9 or later.

#### Replace the PowerSync.Maui Package

The `PowerSync.Maui` package is deprecated. `PowerSync.Common` now includes the native libraries for Android, iOS, and Mac Catalyst.

1. Remove the `PowerSync.Maui` package from your project.
2. Replace the MAUI classes with their equivalents in the `PowerSync.Common.MDSQLite` namespace. Each equivalent takes the same options as the class it replaces:
   - Replace `MAUISQLiteAdapter` with `MDSQLiteAdapter`, which takes `MDSQLiteAdapterOptions`.
   - Replace `MAUISQLiteDBOpenFactory` with `MDSQLiteDBOpenFactory`, which takes `MDSQLiteOpenFactoryOptions`.

   Alternatively, pass `SQLOpenOptions` as shown in [Instantiate the PowerSync Database](#2-instantiate-the-powersync-database).

#### Update Queries

`Get`, `GetOptional`, `GetAll`, and `Watch` no longer use Dapper, and the SDK no longer depends on the `Dapper` package. The SDK does not map rows to objects automatically, and untyped queries no longer return `dynamic` values.

```cs
// Before (v0.x): Dapper matched columns to properties by name
ListResult[] lists = await db.GetAll<ListResult>("SELECT * FROM lists");

dynamic list = await db.Get("SELECT name FROM lists WHERE id = ?", [listId]);
Console.WriteLine(list.name);
```

```cs
// After (v1): ListResult implements IFromRow<ListResult>
List<ListResult> lists = await db.GetAll<ListResult>("SELECT * FROM lists");

// Alternatively, pass a mapper function
List<string> names = await db.GetAll(
    "SELECT name FROM lists",
    null,
    row => row.GetString("name")
);

// Untyped queries return IQueryRow values
IQueryRow list = await db.Get("SELECT name FROM lists WHERE id = ?", [listId]);
Console.WriteLine(list.GetString("name"));
```

Make these changes to your queries:

- For each result type, implement `IFromRow<T>`, generate the mapping code with the alpha source generator, or pass a mapper function. This also applies to schema classes that use `[Column]` attributes. See [Mapping Rows to Objects](#mapping-rows-to-objects).
- Change code that expects `T[]` from `GetAll<T>` or `Watch<T>`. These methods now return `List<T>`.
- Replace `dynamic` results with `IQueryRow` methods, such as `GetString`. `GetAll` and `Watch` without a result type return a `QueryResult`. Its `Rows` property contains the `IQueryRow` values.

#### Update Table Names from OnChange

`PowerSyncDatabase.OnChange` now reports the name of the underlying table instead of the view name. For example, a change to the `todo_lists` table is reported as `ps_data__todo_lists`. Update code that compares the values in `ChangedTables` with view names.

#### Use long Values for Operation IDs and Checkpoints

Operation IDs, write checkpoints, and checkpoint request IDs are now `long` values instead of `string` values. Update code that uses these APIs:

- `CrudBatch` and `CrudTransaction` objects returned by `GetCrudBatch()` and `GetNextCrudTransaction()` take an optional `long?` write checkpoint in their `Complete()` methods.
- `PowerSyncDatabase.HandleCrudCheckpoint()` takes an optional `long?` write checkpoint.
- `ICustomCheckpointRequestConnector.PostCheckpointRequest()` receives a `long` request ID and returns `Task<long>`.

#### Implement `IPowerSyncBackendConnector` with `ICustomCheckpointRequestConnector`

`ICustomCheckpointRequestConnector` no longer extends `IPowerSyncBackendConnector`. It now extends `IAuthenticator`, so a class that implements only `ICustomCheckpointRequestConnector` cannot be passed to `Connect()` as a backend connector. Add `IPowerSyncBackendConnector` to each class that implements `ICustomCheckpointRequestConnector`:

```cs
// Before (v0.x)
class BackendConnector : ICustomCheckpointRequestConnector

// After (v1)
class BackendConnector : IPowerSyncBackendConnector, ICustomCheckpointRequestConnector
```

#### Use `HashSet<string>` instead of `BatchedUpdateNotification`

`DBAdapterEvents.TablesUpdatedEvent.TablesUpdated` is now a `HashSet<string>` of updated table names. It no longer uses the `BatchedUpdateNotification` wrapper, which has been removed (along with `INotification` and `UpdateNotification`).
