<Info>
  PowerSync DevTools is currently available for [Vite](/tools/devtools/vite), [Nuxt](/tools/devtools/nuxt), [Capacitor](/tools/devtools/capacitor), and [Node.js](/tools/devtools/node) apps.
</Info>

Use PowerSync DevTools to:

- Check that the client is connected and up to date, and see sync errors.
- Look at the data on the device, and run SQL on it.
- See which buckets and Sync Streams the client syncs, and how far each one has downloaded.
- See the local changes that wait to upload.
- Inspect the client configuration, such as the endpoint, user ID, connection parameters, and schema.
- Read the SDK logs.
- Test offline behavior: disconnect, reconnect, or clear and re-sync.

Coding agents can query the same client and run sync actions through [MCP tools](/tools/devtools/mcp) when you use Vite, Nuxt DevTools 4, Capacitor, or Node.js.

DevTools runs in development only and adds nothing to a production build.

## How It Works

A host process serves DevTools. The host is your dev server, such as Vite. If your platform has no dev server, the host is your app process. The setup page for your platform tells you which host to use.

```mermaid
flowchart LR
  App["Your app"] -- "live database" --> Host["DevTools host<br/>(dev server or app process)"]
  Host --> UI["DevTools window"]
  Host --> Agent["Coding agent<br/>(MCP)"]
```

DevTools reads from the database that your app has open, so it shows the same data that your app sees.

## DevTools vs. Sync Diagnostics Client

Use DevTools to inspect the client in your running app. Use the [Sync Diagnostics Client](/tools/diagnostics-client) to see the data that the Service syncs to a specific user. You can use both in tandem.

|  | PowerSync DevTools | Sync Diagnostics Client |
| --- | --- | --- |
| **How it connects** | To your running app | With a user JWT and the PowerSync endpoint |
| **What you inspect** | Local SQLite data and sync state in your app | Sync data: buckets, operations, stream subscriptions |
| **Environment** | Development only | Any environment |
| **SDK-specific** | Yes | No. It works with all SDKs. |
