On this route, your app's mutation uploader uses the Supabase client SDK to send each queued change to Supabase's Data API, which is built on PostgREST. You don't deploy a separate write endpoint: Supabase's grants and row-level security (RLS) policies decide which writes each user can make. The [Supabase guide](/integrations/supabase/guide) and the Supabase demo apps use this route.

## Add Grants and RLS Policies

Requests from a signed-in user run as Supabase's `authenticated` role, so your grants and RLS policies for that role must allow every write that your app uploads.

<SupabaseGrantsAndRls />

If a policy or a missing grant denies a write, the [example uploaders](#uploader-examples) drop it. See [How the Uploader Handles Errors](#how-the-uploader-handles-errors).

## Transactions Are Not Atomic

The Supabase client SDK has no transaction support. The uploader sends each change in a transaction as a separate request, and each request commits on its own. If one change in a transaction fails, the changes before it stay in the database.

For example, an app creates a list and its first item in one local transaction. If the insert of the item fails, the list is still created in Supabase.

If your app needs all changes in a transaction to be applied together or not at all, you have two options:

- Use the [Edge Function route](/handling-writes/write-path/supabase-edge-function), which runs the reference write implementation as a Supabase Edge Function and applies each transaction atomically.
- Write a Postgres function that applies the whole transaction, and call it from your uploader with the Supabase client's `rpc()` method.

## How the Uploader Handles Errors

The [example uploaders](#uploader-examples) are based on the Supabase demo apps, such as the React demo's [`SupabaseConnector.ts`](https://github.com/powersync-ja/powersync-js/blob/main/demos/react-supabase-todolist/src/library/powersync/SupabaseConnector.ts). They check the Postgres error code that Supabase returns:

| Error code | Meaning | What the uploader does |
| --- | --- | --- |
| Class `22` | Data exception, such as a type mismatch | Logs the error and marks the transaction complete |
| Class `23` | Constraint violation, such as `NOT NULL`, `FOREIGN KEY`, or `UNIQUE` | Logs the error and marks the transaction complete |
| `42501` | Insufficient privilege, usually a missing grant or an RLS policy that rejects the write | Logs the error and marks the transaction complete |
| Any other error | For example, a network error | Throws, so the SDK retries |

When the uploader marks the transaction complete after an error, it drops the failed change and every change after it in the same transaction. These changes become [rejected writes](/handling-writes/write-path/concepts#rejected-writes). The app's local data reverts after the next sync. The error appears only in the app's logs. For the causes of `42501`, see [Uploads Fail With Error `42501`](/integrations/supabase/guide#uploads-fail-with-error-42501).

The uploader retries every other error, including errors that can never succeed, such as `PGRST204` for a column that doesn't exist in Supabase. Such a transaction becomes a [blocked transaction](/handling-writes/write-path/concepts#blocked-transactions) and holds back every later write until you fix the cause. Check the app's logs for repeated upload errors.

To reduce the number of requests, you can merge consecutive changes to the same table into one request. See [Improve Supabase Connector](/integrations/supabase/connector-performance).

## Uploader Examples

Copy the uploader for your SDK into your app. Each one uploads writes with the Supabase client SDK, as the signed-in user. There is no Supabase uploader for Rust.

The uploaders work with the Supabase authenticator, which gives PowerSync the Supabase Auth session token. If your app doesn't have it yet, copy it from the [Supabase examples](/configuration/app-backend/client-connection-examples#supabase), which show both files for each SDK. Then connect with the authenticator and the uploader, as the comment in each uploader shows.
