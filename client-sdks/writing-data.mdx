PowerSync applies each SQL INSERT, UPDATE, or DELETE immediately to client-side SQLite and records the change in an upload queue. Your UI can react to the local result without waiting for a network round trip.

While connected, the SDK calls your [mutation uploader](/configuration/app-backend/client-side-integration#mutation-uploader). The uploader sends the queued mutations to your write API, where you keep control over authorization, validation, and business logic before you apply them to your source database. The resulting backend state then syncs to clients through PowerSync. If connectivity is interrupted, the mutations stay in the upload queue until the SDK can upload them.

## Basic Write Operations

<CodeGroup>

```typescript TypeScript
// Insert a new todo
await db.execute(
  'INSERT INTO todos (id, created_at, list_id, description) VALUES (uuid(), date(), ?, ?)',
  [listId, 'Buy groceries']
);

// Update a todo
await db.execute(
  'UPDATE todos SET completed = 1, completed_at = date() WHERE id = ?',
  [todoId]
);

// Delete a todo
await db.execute('DELETE FROM todos WHERE id = ?', [todoId]);
```

<Note>
  **Best practice**: Use UUIDs when inserting new rows on the client side. UUIDs can be generated offline/locally, allowing for unique identification of records created in the client database before they are synced to the server. See [Client ID](/sync/advanced/client-id) for more details.
</Note>

## ORM Support

PowerSync integrates with popular ORM libraries, which provide type safety and additional tooling. Using an ORM is often preferable to writing raw SQL queries, especially for common operations.

See [ORM Support](/client-sdks/orms/overview) to learn which ORMs PowerSync supports and how to get started.

## Write Operations and Upload Queue

The upload queue records each write to a synced table as a `PUT` (for `INSERT`), `PATCH` (for `UPDATE`), or `DELETE` operation. See [Write Operations](/handling-writes/write-path/concepts#write-operations) for what each operation contains.

For when and how the SDK calls `uploadData()`, including triggers, throttling, retry behavior, and error handling, see [When `uploadData()` is Called](/configuration/app-backend/client-side-integration#when-uploaddata-is-called). To set up your backend to accept these writes, see [Choosing Your Implementation](/handling-writes/write-path/choosing-your-implementation).

To wait until a write has uploaded and its result has synced back, for example before showing values your backend generates, use a [checkpoint request](/client-sdks/checkpoint-requests#relationship-to-local-writes).
