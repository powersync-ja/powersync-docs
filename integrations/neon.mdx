This guide shows you how to set up PowerSync with [Neon](https://neon.com/) and run a React notes demo app. PowerSync syncs data from Neon Postgres into a SQLite database in your app. The app reads and writes this local database, so it responds instantly and keeps working without a network connection.

The demo app is a fork of Neon's [Data API and Neon Auth demo](https://github.com/neondatabase-labs/neon-data-api-neon-auth) with PowerSync added.

This guide takes 10–15 minutes. Before you start, make sure you have:

- A [Neon](https://console.neon.tech/signup) account
- A [PowerSync Cloud](https://accounts.powersync.com/portal/powersync-signup?s=docs) account
- [pnpm](https://pnpm.io/installation) installed

## Architecture

<Frame caption="Neon + PowerSync architecture">
  ![Diagram of the PowerSync Service syncing data from Neon Postgres to SQLite in the app, and the app uploading writes to Neon through the Neon TypeScript SDK](/images/integration-guides/neon/powersync-docs-diagram-neon-integration.png)
</Frame>

The PowerSync Service replicates data from Neon Postgres and syncs it to each client's SQLite database, based on your Sync Streams. When the app writes to SQLite, the PowerSync SDK also adds the change to an upload queue. While the device is online, the SDK calls the app's `uploadData()` function, which sends queued changes to Neon through the [Neon Data API](https://neon.com/docs/data-api/overview).

Neon Auth handles sign-in. The Data API and PowerSync both accept the JWTs that Neon Auth issues. For more on how PowerSync works, see the [Architecture Overview](/architecture/architecture-overview).

## Configure Neon

### Create a Neon Project

1. In the [Neon Console](https://console.neon.tech), create a project.
2. Enable **Better Auth**. Neon calls this managed Better Auth service [Neon Auth](https://neon.com/docs/auth/overview).
3. Enable the Data API under **Postgres database** > **Data API**, with both of these options selected:
   - **Use Neon Auth:** The Data API accepts JWTs from Neon Auth.
   - **Grant public schema access:** The `authenticated` role can read and write tables in the `public` schema, including tables you create later. This option is not selected by default. The demo app uploads writes as this role, so without these grants its uploads fail.

### Create the Demo Database Schema

The demo app uses [Drizzle](https://orm.drizzle.team/) migrations to create its tables and Row Level Security (RLS) policies.

1. Clone the demo app and install its dependencies:
   ```bash
   git clone https://github.com/powersync-ja/powersync-js.git
   cd powersync-js/demos/react-neon-tanstack-query-notes
   pnpm install
   ```
2. In the Neon Console, open **Connect** and copy the connection string with **Connection pooling** turned off. Neon recommends a direct connection for migrations.
3. Create a `.env` file in the demo directory and add the connection string:
   ```env
   DATABASE_URL=postgresql://neondb_owner:<password>@ep-cool-darkness-123456.c-2.us-east-2.aws.neon.tech/neondb?sslmode=require&channel_binding=require
   ```
4. Run the migration:
   ```bash
   pnpm db:migrate
   ```

The migration creates these tables:

```sql
CREATE TABLE "notes" (
  "id" uuid PRIMARY KEY DEFAULT gen_random_uuid() NOT NULL,
  "owner_id" text DEFAULT auth.user_id() NOT NULL,
  "title" text DEFAULT 'untitled note' NOT NULL,
  "created_at" timestamp with time zone DEFAULT now(),
  "updated_at" timestamp with time zone DEFAULT now(),
  "shared" boolean DEFAULT false
);

CREATE TABLE "paragraphs" (
  "id" uuid PRIMARY KEY DEFAULT gen_random_uuid() NOT NULL,
  "note_id" uuid REFERENCES notes(id),
  "content" text NOT NULL,
  "created_at" timestamp with time zone DEFAULT now()
);
```

The RLS policies let each signed-in user read and write their own notes and paragraphs, and read notes that have `shared` set to `true`.

### Configure Sync Streams

[Sync Streams](/sync/streams/overview) define which data syncs to which users' devices. In the demo app, each user syncs their own notes and paragraphs, plus all shared notes.

1. In the PowerSync Dashboard, go to the **Sync Streams** view.
2. Replace the contents of the editor with the following Sync Config:
   ```yaml
   config:
     edition: 3
   streams:
     user_notes:
       auto_subscribe: true
       # Sync notes and paragraphs belonging to the authenticated user
       queries:
         - SELECT * FROM notes WHERE owner_id = auth.user_id()
         - SELECT paragraphs.* FROM paragraphs
             INNER JOIN notes ON notes.id = paragraphs.note_id
             WHERE notes.owner_id = auth.user_id()
     shared_notes:
       auto_subscribe: true
       # Sync all shared notes to all users (not recommended for production)
       queries:
         - SELECT * FROM notes WHERE shared = TRUE
         - SELECT paragraphs.* FROM paragraphs
             INNER JOIN notes ON notes.id = paragraphs.note_id
             WHERE notes.shared = TRUE
   ```
3. Click **Validate** and fix any errors.
4. Click **Deploy**.

## Run the Demo App

### Configure Environment Variables

Add the following variables to the `.env` file in the demo directory:

```env
# Neon Console > Postgres database > Data API > API URL
VITE_NEON_DATA_API_URL=https://ep-cool-darkness-123456.apirest.c-2.us-east-2.aws.neon.tech/neondb/rest/v1

# Neon Console > Settings > Better Auth > Auth URL
VITE_NEON_AUTH_URL=https://ep-cool-darkness-123456.neonauth.c-2.us-east-2.aws.neon.tech/neondb/auth

# PowerSync Dashboard > Connect > instance URL
VITE_POWERSYNC_URL=https://your-instance-id.powersync.journeyapps.com
```

### Start the App

Start the development server:

```bash
pnpm dev
```

Open [http://localhost:5173](http://localhost:5173) and sign up. Neon Auth accepts requests from `localhost` while **Allow Localhost** is on, which is the default. If you deploy the app, add its domain in the Neon Console under **Settings** > **Better Auth** > **Domains**.

The notes list is empty at first. Create a note, then disconnect your device from the network (for example, turn off Wi-Fi) and edit the note. When you reconnect, the SDK uploads the queued changes, and they appear in the `notes` and `paragraphs` tables in Neon.

<Frame caption="The demo app after creating two notes">
  ![Demo app showing a list of two notes for the signed-in user](/images/integration-guides/neon/demo-app.png)
</Frame>

<Note>
  If a note disappears shortly after you create it, the Data API rejected the upload. The demo app discards uploads that fail with a Postgres permission error (`42501`) and logs `Data upload error - discarding` in the browser console. The next sync then removes the local change. This happens, for example, if you didn't select **Grant public schema access** when you enabled the Data API. To grant access to the demo tables, run `GRANT SELECT, INSERT, UPDATE, DELETE ON notes, paragraphs TO authenticated;` in the SQL Editor.
</Note>

### Test Your Sync Streams (Optional)

To see which data syncs to a specific user, go to **Sync Test** in the PowerSync Dashboard. Generate a development token for a user who signed up in the demo app, and open it in the [Sync Diagnostics Client](/tools/diagnostics-client). Use the user's ID as the token subject. This ID is the `owner_id` value of the user's notes.
