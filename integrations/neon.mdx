This guide shows you how to set up PowerSync with [Neon](https://neon.com/) and run a React notes demo app. The app reads and writes a local SQLite database, so it responds instantly and keeps working without a network connection.

The demo app is a fork of Neon's [Data API and Neon Auth demo](https://github.com/neondatabase-labs/neon-data-api-neon-auth) with PowerSync added.

<Info>
  Comparing PowerSync with Neon Realtime? See [PowerSync vs Neon Realtime](/resources/alternatives/neon-realtime).
</Info>

Before you start, make sure you have:

- A [Neon](https://console.neon.tech/signup) account
- A [PowerSync Cloud](https://accounts.powersync.com/portal/powersync-signup?s=docs) account
- [pnpm](https://pnpm.io/installation) installed

## Architecture

<Frame caption="Neon + PowerSync architecture">
  ![Diagram of the PowerSync Service syncing data from Neon Postgres to SQLite in the app, and the app uploading writes to Neon through the Neon TypeScript SDK](/images/integration-guides/neon/powersync-docs-diagram-neon-integration.png)
</Frame>

The PowerSync Service replicates data from Neon Postgres and syncs it to each client's SQLite database, based on your Sync Streams. When the app writes to SQLite, the PowerSync SDK also adds the change to an upload queue. While the device is online, the SDK calls the app's `uploadData()` function, which sends queued changes to Neon through the [Neon Data API](https://neon.com/docs/data-api/overview).

Neon Auth handles sign-in. The Data API and PowerSync both accept the JWTs that Neon Auth issues. For more on how PowerSync works, see the [Architecture Overview](/architecture/architecture-overview).

## Configure Neon

### Create a Neon Project

Create a project with [Neon Auth](https://neon.com/docs/auth/overview), Neon's managed Better Auth service, and the [Data API](https://neon.com/docs/data-api/overview).

<Tabs>
  <Tab title="Web UI">
    1. In the [Neon Console](https://console.neon.tech), create a project.
    2. Enable **Better Auth**.
    3. Enable the Data API under **Postgres database** > **Data API**. Keep **Use Neon Auth** selected and select **Grant public schema access**, which is off by default.
  </Tab>
  <Tab title="CLI">
    1. Install the Neon CLI and log in:
       ```bash
       npm i -g neon@latest
       neon login
       ```
    2. Create a project. The output includes the project ID, which the following commands use as `<project-id>`:
       ```bash
       neon projects create --name powersync-neon-notes --region-id aws-us-east-2
       ```
    3. Enable Neon Auth and the Data API:
       ```bash
       neon neon-auth enable --project-id <project-id>
       neon data-api create --project-id <project-id> --database neondb --auth-provider neon_auth --add-default-grants
       ```
  </Tab>
</Tabs>

The demo app uploads writes through the Data API as the `authenticated` role. **Grant public schema access** (`--add-default-grants` in the CLI) gives this role read and write access to tables in the `public` schema, including tables you create later. Without these grants, the demo app's uploads fail.

### Create the Demo Database Schema

The demo app uses [Drizzle](https://orm.drizzle.team/) migrations to create its tables and Row Level Security (RLS) policies.

1. Clone the demo app and install its dependencies:
   ```bash
   git clone https://github.com/powersync-ja/powersync-js.git
   cd powersync-js/demos/react-neon-tanstack-query-notes
   pnpm install
   ```
2. Get a direct connection string:
   - **Web UI:** In the Neon Console, click **Connect**, turn off **Connection pooling**, and copy the connection string.
   - **CLI:** Run `neon connection-string --project-id <project-id>`. It returns a direct connection string by default.
3. Create a `.env` file in the demo directory and add the connection string:
   ```env
   DATABASE_URL=postgresql://neondb_owner:<password>@ep-cool-darkness-123456.c-2.us-east-2.aws.neon.tech/neondb?sslmode=require&channel_binding=require
   ```
4. Run the migration:
   ```bash
   pnpm db:migrate
   ```

The migration creates these tables:

```sql
CREATE TABLE "notes" (
  "id" uuid PRIMARY KEY DEFAULT gen_random_uuid() NOT NULL,
  "owner_id" text DEFAULT auth.user_id() NOT NULL,
  "title" text DEFAULT 'untitled note' NOT NULL,
  "created_at" timestamp with time zone DEFAULT now(),
  "updated_at" timestamp with time zone DEFAULT now(),
  "shared" boolean DEFAULT false
);

CREATE TABLE "paragraphs" (
  "id" uuid PRIMARY KEY DEFAULT gen_random_uuid() NOT NULL,
  "note_id" uuid REFERENCES notes(id),
  "content" text NOT NULL,
  "created_at" timestamp with time zone DEFAULT now()
);
```

The RLS policies let each signed-in user read and write their own notes and paragraphs, and read shared notes and their paragraphs.

### Configure Neon Auth

The demo app sends PowerSync the JWT that Neon Auth issues for the signed-in user. To verify these JWTs, PowerSync needs two values from Neon:

- **JWKS URL:** The public keys that Neon Auth publishes as a JSON Web Key Set (JWKS), for example `https://ep-cool-darkness-123456.neonauth.c-2.us-east-2.aws.neon.tech/neondb/auth/.well-known/jwks.json`.
- **JWT audience:** The origin of your Neon **Auth URL**, which is the URL without the path and without a trailing `/`, for example `https://ep-cool-darkness-123456.neonauth.c-2.us-east-2.aws.neon.tech`. PowerSync rejects a token if its `aud` value doesn't match exactly.

You also enable development tokens, which you use to [test your Sync Streams](#test-your-sync-streams-optional) at the end of this guide.

<Tabs>
  <Tab title="Web UI">
    Find the **Auth URL** and **JWKS URL** in the Neon Console under **Settings** > **Better Auth**. Then, in the PowerSync Dashboard, go to the **Client Auth** view and set the following fields:

    - **Development tokens:** Enable this setting.
    - **JWKS URI:** Enter the **JWKS URL** from Neon.
    - **JWT Audience:** Enter the origin of the **Auth URL** from Neon.

    Then click **Save and Deploy**.
  </Tab>
  <Tab title="CLI">
    `neon neon-auth status --project-id <project-id>` prints the Auth URL as `base_url` and the JWKS URL as `jwks_url`. Add a `client_auth` section to `powersync/service.yaml`:

    ```yaml
    client_auth:
      jwks_uri: https://ep-cool-darkness-123456.neonauth.c-2.us-east-2.aws.neon.tech/neondb/auth/.well-known/jwks.json
      additional_audiences:
        - https://ep-cool-darkness-123456.neonauth.c-2.us-east-2.aws.neon.tech
      allow_temporary_tokens: true
    ```

    You deploy this configuration together with your Sync Config in the next step.
  </Tab>
</Tabs>

### Configure Sync Streams

[Sync Streams](/sync/streams/overview) define which data syncs to which users' devices. In the demo app, each user syncs their own notes and paragraphs, plus all shared notes and their paragraphs.

Use the following Sync Config:

```yaml
config:
  edition: 3
streams:
  user_notes:
    auto_subscribe: true
    # Sync notes and paragraphs belonging to the authenticated user
    queries:
      - SELECT * FROM notes WHERE owner_id = auth.user_id()
      - SELECT paragraphs.* FROM paragraphs
          INNER JOIN notes ON notes.id = paragraphs.note_id
          WHERE notes.owner_id = auth.user_id()
  shared_notes:
    auto_subscribe: true
    # Sync all shared notes to all users (not recommended for production)
    queries:
      - SELECT * FROM notes WHERE shared = TRUE
      - SELECT paragraphs.* FROM paragraphs
          INNER JOIN notes ON notes.id = paragraphs.note_id
          WHERE notes.shared = TRUE
```

<Tabs>
  <Tab title="Web UI">
    1. In the PowerSync Dashboard, go to the **Sync Streams** view.
    2. Replace the contents of the editor with the Sync Config above.
    3. Click **Validate** and fix any errors.
    4. Click **Deploy**.
  </Tab>
  <Tab title="CLI">
    Replace the contents of `powersync/sync-config.yaml` with the Sync Config above. Then deploy the full configuration, which includes the database connection, client auth, and Sync Config:

    ```bash
    export POWERSYNC_DATABASE_PASSWORD=<powersync_role password>
    powersync deploy
    ```
  </Tab>
</Tabs>

## Run the Demo App

### Configure Environment Variables

Add the following variables to the `.env` file in the demo directory:

```env
# Neon Console > Postgres database > Data API > API URL
VITE_NEON_DATA_API_URL=https://ep-cool-darkness-123456.apirest.c-2.us-east-2.aws.neon.tech/neondb/rest/v1

# Neon Console > Settings > Better Auth > Auth URL
VITE_NEON_AUTH_URL=https://ep-cool-darkness-123456.neonauth.c-2.us-east-2.aws.neon.tech/neondb/auth

# PowerSync Dashboard > Connect > instance URL
VITE_POWERSYNC_URL=https://your-instance-id.powersync.journeyapps.com
```

If you use the CLI, `neon data-api get --project-id <project-id> --database neondb` prints the Data API URL, and `neon neon-auth status --project-id <project-id>` prints the Auth URL as `base_url`. Your PowerSync instance URL is `https://<instance-id>.powersync.journeyapps.com`, where `<instance-id>` is the `instance_id` value in `powersync/cli.yaml`.

### Start the App

Start the development server:

```bash
pnpm dev
```

Open [http://localhost:5173](http://localhost:5173) and sign up. Neon Auth accepts requests from `localhost` while **Allow Localhost** is on, which is the default. If you deploy the app, add its domain in the Neon Console under **Settings** > **Better Auth** > **Domains**.

The notes list is empty at first. Create a note, then disconnect your device from the network (for example, turn off Wi-Fi) and edit the note. When you reconnect, the SDK uploads the queued changes, and they appear in the `notes` and `paragraphs` tables in Neon.

<Frame caption="The demo app after creating two notes">
  ![Demo app showing a list of two notes for the signed-in user](/images/integration-guides/neon/demo-app.png)
</Frame>

<Note>
  If a note disappears shortly after you create it, the Data API rejected the upload with a permission error (`42501`), and the demo app discarded the change. To grant access to the demo tables, run `GRANT SELECT, INSERT, UPDATE, DELETE ON notes, paragraphs TO authenticated;` in the SQL Editor.
</Note>

### Test Your Sync Streams (Optional)

To see which data syncs to a specific user, generate a development token for a user who signed up in the demo app, and open it in the [Sync Diagnostics Client](/tools/diagnostics-client). Use the user's ID as the token subject. This ID is the `owner_id` value of the user's notes.

<Tabs>
  <Tab title="Web UI">
    In the PowerSync Dashboard, go to the **Sync Test** view. Enter the user ID as the token subject, then click **Generate token** and **Launch Sync Diagnostics Client**.
  </Tab>
  <Tab title="CLI">
    In the demo directory, run the following command and paste the token into the [Sync Diagnostics Client](https://diagnostics-app.powersync.com):

    ```bash
    powersync generate token --subject=<user-id>
    ```
  </Tab>
</Tabs>
